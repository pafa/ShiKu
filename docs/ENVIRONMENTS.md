# 本地试玩、回归与线上对照

从要验证的公开仓库工作副本启动。Node.js 22.12 及以上即可，试玩和回归各有独立的本地房间、访客与候位队列。

| 用途 | 地址 | 运行的内容 |
| --- | --- | --- |
| 线上版本的本地对照 | `127.0.0.1:4173` | 已与当前线上发布记录核对的干净公开导出，用于比较页面、模型、音轨与展品表现。 |
| 功能试玩 | `127.0.0.1:4174` | 当前功能分支，可含未提交修改。用浏览器边改边看。 |
| 回归验证 | `127.0.0.1:4175` | 指定提交的干净 Git 工作副本。启动时检查提交和工作树，有暂存、未暂存或未跟踪的改动即退出。 |

## 启动试玩或回归

在各自的工作副本执行对应命令。试玩允许未提交的修改。做回归时先在独立 Git 工作副本检出待审提交，启动后将终端显示的提交号与 PR 核对。回归命令只接受有 Git 历史的干净检出；验证下载的发布归档请按下方的“更换线上对照”操作。

```sh
node scripts/start-local.mjs feature
node scripts/start-local.mjs test
```

两条命令分别在各自终端运行。用浏览器打开终端列出的地址，检查首页与实际修改的展馆入口。若端口被占，可显式指定另一端口，例如 `node scripts/start-local.mjs test --port 4275`。按 Ctrl+C 关闭该进程，也会释放它的房间和端口。后端代码变化后重启进程。切换分支或提交后也应重启，以免混用已载入的服务逻辑和磁盘上的新资源。

## 更换线上对照

先在发布记录中找到线上 Worker Version ID 对应的 Git 提交、文件树和归档 SHA-256。核对[线上版本接口](https://shiku.xiaoha.org/api/version)及下载归档的摘要，在独立新目录解包。然后从导出根目录验证：

```sh
node scripts/check-public-release.mjs --dir . --files-only
node server/museum.mjs --host 127.0.0.1 --port 4273
```

先在临时端口检查首页、相关展项及 `/api/room`。成功后从原终端停止自己管理的旧对照，关闭临时进程，从刚刚验证的同一目录执行 `node server/museum.mjs --host 127.0.0.1 --port 4173`。保留旧归档与收据，可以用同一流程恢复。如果旧端口归属未知，保留它，继续通过临时端口验证。

## 多人状态与线上发布

上述 Node 房间的数据保存在进程内，重启后清空。要验证 Cloudflare 房间重启后的轨迹、席位和候位恢复，请在打包后的独立候选中按[本地 Worker 演练](../deploy/cloudflare/README.md)运行 Wrangler 的 `dev --local`，为每轮实验使用独立的 `--persist-to` 目录。同一轮重启恢复测试要沿用该目录。

上线时用发布记录串起 Git 提交及文件树、已校验归档的 SHA-256、获准切换的 Cloudflare Version ID 和实际 Deployment ID。切流后从域名回读 Version ID，对照发布物抽验首页、音轨及展品文件，再走一次入馆流程。Node 对照房间与线上 SQLite 房间各自保存访客状态。
